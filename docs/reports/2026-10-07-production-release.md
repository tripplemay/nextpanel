### 不是零停机

迁移必须暂停旧后端，防止旧分享接口读取轮换后的主 token。构建在独立目录完成后才停服。
PM2 停服至新数据库就绪约 **25 秒**。外网 72 组连续采样中有 3 组观察到 502：

- 最后正常样本：08:35:38 UTC。
- 异常样本：08:35:45、08:35:52、08:36:00 UTC（最后一组登录已恢复、订阅仍 502）。
- 双端恢复样本：08:36:08 UTC；之后样本均正常。

因此本次不能声明“外网完全无影响”或“零停机”。代理转发进程没有重启，业务前后验证没有新增失败；但有限采样不等于对所有用户会话零丢包的证明。旧主链接失效属于用户明确接受的安全变更。

## 回退

生产面板完整旧目录、环境、数据库和 SHA-256 保存在：

```text
/opt/backups/nextpanel/releases/ad90a5671e4f303cb178e61aa6091a4f6cbcb711/
```

在生产主机执行面板回退（会暂停面板、恢复快照，丢弃发布后的数据库写入并恢复旧主 token）：

```sh
bash /opt/apps/nextpanel/scripts/deploy-release.sh rollback ad90a5671e4f303cb178e61aa6091a4f6cbcb711
```

每台已升级 Agent 保留旧二进制、配置和 unit，升级期间有独立 240 秒自动回退 timer；只有真实新版心跳与转发服务不变均通过才取消 timer。事后手动回退该机器：

```sh
DIR=/opt/backups/nextpanel-agent/release-agent-v1-7-0
rm -- "$DIR/CONFIRMED"
bash "$DIR/upgrade.sh" rollback "$DIR"
```

随后必须检查旧版本真实心跳和转发服务；不要只以 `systemctl active` 判断完成。运行中的正式 Agent 已确认，因此当前不保留倒计时回退任务。面板整机目录切换的自动异常回退有脚本回归覆盖，真实生产数据库有隔离恢复验收；**没有为了演练而再次回退正在服务的新面板**。
