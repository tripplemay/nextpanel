# CF 地区拨测预算评估

核验日期：2026-11-01。范围：本项目独立 CF Web 函数，不包含旧 `gfw-check`。
结论：调用次数费用很低；主要成本是 **配置内存 × 实际计费时长**。
此前 200 批/月是按双请求都耗尽超时的极端预留，不是日常用量预测。

## 实际账单证据

通过腾讯云费用中心只读核验，广州 CF 探针在北京时间
2026-11-01 00:00:00–00:59:59 的小时明细如下；未触发新探测或修改云配置。

| 组件 | 用量 | 单价 | 明细费用（元） |
| --- | ---: | ---: | ---: |
| 资源使用量 | 54.22450000 GB·s | 0.00011108 / GB·s | 0.00602326 |
| HTTP 调用 | 16 次 | 0.00000133 / 次 | 0.00002128 |
| 外网出流量 | 0.00033322 GB | 0.80 / GB | 0.00026658 |
| 合计 | | | **0.00631112** |

这不是整个账号费用：排除了同页 `gfw-check` 的三项明细。
控制台提示当月账单未最终出账、可能延迟；不将尚未显示的费用视为永远为零。
探针配置仍为 512 MB、无预置并发、未配置 CLS 日志投递。

面板每批最多调用 `/capabilities`、`/probe` 各一次。按 16 次调用折算
8 批，得到 **6.7780625 GB·s/批，约 0.00078889 元/批**。
在 512 MB 下相当于两次请求合计约 13.56 秒计费时间，而非 8 个 IP
分别作为 8 次云函数调用。候选在一批内部以 4 路并发执行。
此推导假设该小时调用均为面板双请求批次；它是小样本基准，不是逐请求审计。

## 现行中国站价格与计算口径

- 资源：0.00011108 元/GB·s；HTTP 调用：0.0133 元/万次；
  广州、成都外网/响应出流量：0.80 元/GB。
  [官方定价](https://cloud.tencent.com/document/product/583/12281)
- 不预设免费额度、优惠券或已购套餐。中国站文档说明开通超过三个月
  使用按量计费；不能套用国际站美元或旧基础套餐说明。
  [免费试用说明](https://cloud.tencent.com/document/product/583/12282)、
  [计费概述](https://cloud.tencent.com/document/product/583/17299)
- 1 MiB 下载进入探针，不应直接乘外网出流量单价当作上传费用。
  TLS/请求/ACK 等出向流量仍计费，返回面板的 JSON 也要核对响应流量。
  跨服务 CLS、COS、NAT 等如启用应另外计入，本方案不新增 CVM/NAT/预置实例。
  临时存储保持 512 MB，关闭会话保持，避免额外存储或会话闲置费用。
  [计费项介绍](https://cloud.tencent.com/document/product/583/63306)
- 计费依据是配置内存和计费时长，不是 curl 测得的单条线路延迟。
  冷启动、失败/超时、鉴权失败以及手工调用可能增加实际费用。

## 广州 + 成都、4 个托管节点的月度推算

同一托管节点被多个订阅引用只调度一次，不按订阅数或在线用户数乘算。
Clash 本地测速和 HTTP provider 下载不触发 SCF 拨测，不能混入函数调用次数。
月批数 = 节点数 × 测点数 × 每日批数 × 天数。下表按 30 天计算，
假定成都用量与上述广州样本相同；**成都尚未实测**。

| 服务端节奏 | 批/月 | HTTP 调用/月 | 估算合计（元/月） |
| --- | ---: | ---: | ---: |
| 旧全局上限 | 最多 200 | 最多 400 | 0.16，但无法持续服务 |
| 每 8 小时两轮 | 1,440 | 2,880 | 1.14，长时间只有陈旧通用候选 |
| 每 30 分钟 | 11,520 | 23,040 | 9.09，紧贴有效期、无抖动余量 |
| 每 20 分钟 | 17,280 | 34,560 | 13.63 |
| **每 15 分钟** | **23,040** | **46,080** | **18.18** |
| 每 5 分钟 | 69,120 | 138,240 | 54.53 |

15 分钟方案的费用拆分为计算 17.35、调用 0.06、网络 0.77 元。
31 天约 18.78 元。若平均资源使用量翻倍而网络不变，约 35.52 元/30 天，
会超预算；不能把一次低价样本说成长期账单保证。

复算：`node scripts/cf-probe/estimate-cost.mjs`。脚本支持按实际 GB·s、
网络用量和额外响应流量修改参数，不发起任何云调用。

## 已确认的上线目标与控制

用户已确认：**广州 + 成都、4 个 CF 节点、每 15 分钟、30 元/月**。
应用配置目标：`LOW_BUDGET=false`、`INTERVAL_MINUTES=15`、
`MAX_MONTHLY_BATCHES=25000`（均带 `CF_OPTIMIZATION_` 前缀）。

- 25,000 批覆盖 31 天正常 23,808 批，额外 1,192 批包含失败和人工验证。
  按样本满额度约 19.72 元；仍保留约 10 元缓冲。额度是全局 UTC 月，
  云账单按其账期统计，两者不是同一个金融限额。
- 每测点每日正常候选测试：4 × 96 × 8 = 3,072，低于 5,000 上限。
  每个测点仍最多 100 MiB/日的下载载荷预约，不代表全部网络账单上限。
- 成都先限制一个节点，身份校验和连续两轮成功后扩到四个；广州登记地区前
  先升级 worker。两地区各自鉴权，不复制旧 GFW 函数、不使用新 CVM。
- 上线后核对 24/48 小时账单、成功率、批次平均 GB·s、候选新鲜度和失败退避；
  按实际剩余天数滚动预测。建议费用 20/25 元告警，接近 30 元暂停本拨测任务。
- 应用鉴权不阻止匿名请求进入 SCF 计费；手工调用也可能绕过面板配额。
  告警不是自动停费；本次代码没有设置云端预算告警或自动冻结。
- 暂停或回退仍保留已验证默认 CDN，过期候选移除，无安全地址则拒绝；
  不回退源站、不更改主链接或分享 token。

本文件记录预算与发布目标，**不代表成都函数已创建或生产频率已切换**。
